# LightNote 更新与开发日志 (Changelog)

### V2.2.20 (2026-10-16)

**版本定位**
汇总 2.2.19 正式版之后的图片、表格与编辑可靠性改进，统一 Windows、Web 和 Android 版本号。升级保留原有笔记、附件及账号配置。

**Windows**

* 长笔记连续回车与 Shift+Enter 时正文跟随光标滚动；底部重复留白合并为一处，默认字号下实测末行光标距下边缘约 28px，手动向上阅读不会被强制拉回。
* 软件来源名称仅移除末尾 .exe，忽略大小写，例如 SnippingTool.exe 显示为 SnippingTool；保留文档后缀、网页来源及名称中的其他点号。安装升级不自动批量改写旧笔记。
* 图片解码、导入、压缩及 SQLite 自动保存使用后台处理；文字和附件独立同步，图片传输不再阻塞文字同步，修复附件请求期间的数据库锁占用及连续输入取消旧保存时的误报。

**Windows、Web 与 Android 共用改进**

* 图片采用固定显示尺寸：普通图片以 1080、竖长手机图片以 360 个布局像素为基准，小图不放大；预设比例与手动尺寸保存后保持，窄窗口按可用宽度缩小。
* 截图优先保留原始像素与清晰度。Windows 的 PNG 使用无损处理，WebP 无损处理或保留原文件；Web/Android 保留 PNG、WebP 原文件。JPEG 照片长边上限为 3200、重编码质量参数为 90；超出尺寸上限时执行缩小，其余仅在有体积收益时采用处理结果。
* 表格默认总宽 900，首次按内容估算列宽并保存；旧默认 1080 按比例兼容，手动总宽保持。增加列宽输入和平均分配，内部竖线调整相邻两列、总宽不变；最右边框仅改变末列，前面各列保持，支持取消、撤销重做与保存重开。
* 表格普通边框保持 1px，拖动绿色高亮为 3px，边界附近 8px 可开始拖动；窄窗口允许表格横向滚动。

**验证与发布状态**
Windows 98 项业务测试、41 项桌面编辑器测试、33 项网页测试及 7 组原生界面检查通过；覆盖图片粘贴期间继续输入、表格尺寸与拖动、撤销重做、保存重开、回车跟随和底部距离。Windows 自包含构建及 Android assembleRelease/lintRelease 通过，APK v2 签名有效、证书与旧版一致，版本为 2.2.20 / code 25。发布提供 Windows 便携包、安装器、Android APK 和 SHA-256 清单。真实登录和跨设备同步沿用既有功能，本轮未代用户完成实机登录验收。

### V2.2.19 后续开发版 (2026-10-15)

**版本定位**
记录 2026-10-14 至 2026-10-15 完成的图片清晰度、固定显示宽度、表格列宽及后台处理优化。Windows 本地开发程序已更新，沿用 2.2.19 版本号；本条所列优化尚未正式发布。

**主要修改**

* **图片显示宽度**：普通图片默认基准上限 1080 个布局像素，手机竖长图 360，小图按自然尺寸及屏幕像素比取更小值。25% / 50% / 75% / 100% 按该基准计算并保存固定目标宽度；正文区域更窄时临时缩小，恢复宽窗口后回到目标。已有可识别的默认图片跟随新规则，手动比例及拖拽尺寸保留。
* **截图清晰度**：Windows 沿用 SkiaSharp 4.153.1；PNG 保留原分辨率，无损编码后有体积收益才采用，否则保留原文件；WebP 使用显式无损编码或原文件，GIF 保留原文件。取消竖长截图自动缩半及 PNG 按体积转有损 WebP 的规则；旧有损文件需要原图才能恢复清晰度。
* **照片压缩**：JPEG 照片长边最多 3200 像素、重编码质量 90；超出尺寸上限时执行缩小。网页源码同步该照片规则，PNG / WebP 则保留原文件。
* **表格初始布局**：无有效尺寸的表格默认总宽 900 个布局像素；按表头及各列较长文本估算初始列宽，保留间距并限制个别超长内容的影响。初次确定后保存，不随继续输入或窗口变化重新分配；列数较多时保留最小可用列宽。窗口更窄时横向滚动，图片仍使用独立的 1080 / 360 规则。
* **表格列宽操作**：增加“列宽”数字输入、“应用列宽”和“平均分配”；拖动内部列分隔线时显示绿色高亮和左右光标，在相邻列之间分配宽度并保持总宽度。拖动中只预览，松手后提交一次正文变更；支持撤销重做、取消拖动、整列更新、表头和合并单元格，以及保存重开后保持尺寸。
* **表格总宽度**：最右侧边框支持左右拖动，只改变最后一列宽度，前面各列与左边框位置保持不变；最后一列最小 80 个布局像素。内部竖线仍只调整相邻列占比，总宽不变。普通边框为 1px，内部竖线与右边框的绿色高亮统一为 3px，鼠标命中范围仍保留边界附近 8px。手动总宽记录为自定义尺寸，保存重开不会被默认 900 或旧默认 1080 的兼容规则重置。
* **已有表格兼容**：旧默认总宽 1080 按 900/1080 比例缩到 900，保留各列相对宽度，包括已调整过的列分配，不重新按内容估算。补充默认／自定义总宽标记，转换后不会因重开继续缩小；其他自定义总宽保留。旧表格通过正常打开、保存与同步记录新尺寸。
* **Windows 后台处理**：图片 Base64 解码、导入、压缩、附件存储和自动保存中的 SQLite 写入移到后台，图片导入限并发以控制内存。文字／笔记本与图片采用独立同步入口及互斥锁，文字同步不等待附件传输；图片网络请求前释放数据库 reader 和连接，修复已复现的附件表锁。上传只使用本地处理后的文件，失败保留重试队列，分别显示文字和图片状态；连续输入取消旧防抖保存时不再误报保存失败。

**各平台实际更新**

* **Windows**：主窗口和独立笔记窗口共用编辑器均适用；本地开发程序已构建更新，最终编辑器资源于 2026-10-15 01:25 更新并重启，桌面入口仍指向原项目的开发目录。后台导入、SQLite 写入和文字／附件分离同步属于 Windows C# 宿主的实际改动。
* **Web**：共用图片显示、表格尺寸及列宽操作源码已更新，照片 3200 / 90 与截图原文件保留策略已进入生产构建并通过测试；本次没有部署 GitHub Pages、Cloudflare Pages、Firebase Hosting 或其他线上站点。Windows 的后台线程改动不代表网页已实现对应的 Web Worker 处理。
* **Android**：共用前端源码包含上述显示和表格规则，但本次没有重新构建、签名或安装 APK；当前正式下载 APK 尚未包含这些后续优化。

**验证情况**

* 最新 39 项编辑器测试、32 项网页测试和两端前端构建通过；覆盖旧表格比例缩放、合并单元格、重开不重复缩小、自定义总宽保留，以及图片 1080 / 360、预设比例和旧默认兼容。
