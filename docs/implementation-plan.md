# 轻量笔记软件实施路线

## 1. 产品目标

构建一款 Windows、PC 优先的个人笔记软件，核心原则是：

- 打开快、记录快、搜索快。
- 文本和图片是第一等内容，Markdown 只是后续补充。
- SQLite 中的本地数据始终可用，Firebase 只承担跨设备同步。
- 优先保证数据可靠与可导出，不追求协作、AI、OCR 或复杂知识图谱。

第一版的主界面采用三栏结构：笔记本、笔记列表、编辑器。顶部只保留搜索、新建、同步状态和设置。

## 2. 技术方案

### 桌面端

- .NET 10、C#、WPF。
- CommunityToolkit.Mvvm 管理命令、状态通知和页面模型。
- Microsoft.Extensions.DependencyInjection 管理服务依赖。
- WebView2 仅承载富文本编辑器；窗口、导航、搜索、设置和文件操作均由 WPF 负责。
- Tiptap/ProseMirror 作为编辑器内核，使用 React + Vite 构建为随程序发布的本地静态资源。

### 本地数据

- Microsoft.Data.Sqlite。
- SQLite FTS5 负责标题与正文全文搜索。
- 图片保存在应用数据目录，数据库只保存相对路径、哈希值和元数据。
- 所有日期统一存储为 UTC，界面显示时转换为本地时间。

### 云同步

- Firebase Authentication：第一阶段使用邮箱密码登录。
- Cloud Firestore：同步笔记、笔记本和附件元数据。
- Firebase Storage：同步原始图片。
- C# 同步服务通过 Firebase REST API 工作，不在客户端嵌入服务账号密钥。
- SQLite 是本地事实来源；网络不可用时全部编辑能力照常工作。

## 3. 建议的代码结构

```text
LightNote.sln
├── src/
│   ├── LightNote.App/              WPF 界面、窗口、ViewModel
│   ├── LightNote.Core/             实体、用例、同步规则、接口
│   └── LightNote.Infrastructure/   SQLite、文件、Firebase 实现
├── editor/                         Tiptap 编辑器前端
├── tests/
│   ├── LightNote.Core.Tests/

```

不在第一阶段拆出更多项目。只有当同步或导入导出明显膨胀时才继续拆分。

## 4. 核心数据模型

### notes

- `id`：本地生成的 UUID。
- `notebook_id`。
- `title`。
- `body_json`：编辑器的规范内容。
- `body_html`：导出和兼容用途的缓存。
- `body_text`：搜索与摘要用途的纯文本缓存。
- `is_pinned`。
- `created_at`、`updated_at`。
- `deleted_at`：软删除和同步删除标记。
- `version`：每次保存递增。
- `sync_state`：clean、dirty、syncing、error。

### notebooks

- `id`、`name`、`sort_order`。
- `created_at`、`updated_at`、`deleted_at`。

首版只做一级笔记本，不做无限层级目录。

### attachments

- `id`、`note_id`。
- `relative_path`、`cloud_path`。
- `mime_type`、`size`、`width`、`height`。
- `sha256`：避免重复保存相同图片。
- `created_at`、`deleted_at`、`sync_state`。

### note_versions

- `id`、`note_id`、`version`。
- `body_json`、`title`、`created_at`、`source_device_id`。

只保留有限数量的本地历史版本，例如每篇最近 20 个版本。

### sync_outbox

- `id`、`entity_type`、`entity_id`、`operation`。
- `local_version`、`attempt_count`、`next_attempt_at`、`last_error`。

本地事务提交笔记时同时写入 outbox，避免出现“笔记已保存但没有进入同步队列”的状态。

## 5. WebView2 编辑器协议

WPF 与编辑器只通过结构化 JSON 消息通信，不拼接执行用户输入的 JavaScript。

主要消息：

- `editor.ready`：编辑器加载完成。
- `note.load`：WPF 向编辑器发送笔记内容。
- `note.changed`：编辑器返回 JSON、HTML 和纯文本。
- `attachment.insert`：WPF 保存图片后通知编辑器插入本地资源 URL。
- `editor.command`：粗体、标题、列表、撤销等命令。
- `editor.state`：当前选区格式，用于更新工具栏状态。

图片粘贴流程：编辑器拦截 Clipboard 图片，传给 WPF；WPF 计算哈希并保存到附件目录，写数据库，再返回可显示的本地 URL。拖入图片复用同一流程。

- 强制关闭后，已显示“已保存”的内容不会丢失。

### V0.8：多平台迁移

目标：用公开、可移植的导出格式承接常见笔记软件数据，避免依赖私有数据库或在线账号授权。

实现：

- 解析印象笔记 ENEX，并兼容有道云笔记导出的 ENEX；保留标题、正文、创建/修改时间和标签文字。
- 解析 Google Takeout 中逐篇导出的 Keep JSON；保留清单勾选状态、标签、置顶和时间。
- 识别中英文 CSV 标题、正文、标签及时间列，支持带引号的逗号和跨行正文。
- 含多个 `article` 条目的 HTML 自动拆为多篇；普通 HTML、浮墨 HTML 和每篇一文件的网页导出继续按文件导入。
- 文件夹中同名 Keep JSON/HTML 成对存在时优先 JSON，避免同一篇笔记重复导入。
- ENEX/Keep 中暂不能落库的附件保留占位说明和结果警告；损坏 XML/JSON 只作为单项失败。

兼容边界：

- 印象笔记：直接支持 ENEX、HTML。
- 有道云笔记：直接支持 ENEX；私有 `.ynote` 暂不解析。
- Google Keep：支持解压后的 Takeout `Keep` 文件夹；暂不直接读取整个 Takeout 压缩包。
- 浮墨笔记：支持官方 HTML 导出；具体拆分粒度取决于导出页是否包含独立条目结构。
- 为知笔记、WPS 便签/WPS 笔记、小米云笔记：支持这些产品能够导出的 HTML、Markdown、TXT 或 CSV；私有容器和云端接口不作不可靠推断。

验收：

- 单个 ENEX 内的多篇笔记分别创建，时间与标签文字可验证。
- Keep 清单、标签和置顶状态导入正确。
- CSV 跨行内容不会错误拆行。
- 损坏的 ENEX/JSON 不影响同批其他来源文件。

## 8. 实施原则

- 每次只实现一个可验收版本，不同时铺开多个未完成子系统。
- 每个版本结束时生成可运行安装包并使用真实笔记试用。
- 数据库迁移一旦发布，只追加新迁移，不重写历史迁移。
- 任何云端失败都不能阻止本地保存。
- 先保证恢复和导出，再增加高级功能。
- 不直接 fork 大型笔记软件；只借鉴公开设计并遵守各自许可证。
