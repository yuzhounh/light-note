# LightNote 基础编辑可靠性检查

更新日期：2026-10-13。状态：本地修复、测试和开发版重新构建均已完成。

## 已修复的问题

1. **含图片笔记的编辑和保存被异常打断。** 粘贴来源、表格工具栏监听器误放在图片组件里，引用组件作用域外的变量。每张图片都注册一组监听器，移动光标、回车、编辑和调节图片尺寸时会报错。已移到整个编辑器的作用域，只注册一次。
2. **表格操作栏存在同类作用域错误。** 工具栏状态和按钮定义现在都由编辑器管理；含图片和不含图片的表格笔记均已验证增行操作及保存。
3. **旧保存结果回退最新草稿。** 保存第一版期间继续输入第二版，旧保存完成会把列表模型退回第一版。已通过受控延迟测试复现并修复；取得保存锁后重新检查草稿版本，完成旧写入后继续展示最新草稿。
4. **打开已有笔记时改变内容结构。** 原先把保存的正文送入外部粘贴清理，会删除空列表项和连续换行、合并标题和链接段落或重新解释字面公式文本。现在直接按笔记文档解析保存的 HTML，粘贴清理只用于外部粘贴。
5. **粘贴来源迟到回复影响下一篇笔记。** 切换、清空笔记时注销未完成的来源请求，避免将来源插入其他笔记。
6. **重复扩展注册。** StarterKit 的内置链接、下划线与自定义扩展重名；已禁用重复的内置扩展。普通点击链接留在编辑流程，Ctrl+点击打开链接。
7. **所有应用窗口统一为原生 Tall 标题栏。** 按用户选定路线接入 Windows App SDK Foundation，系统绘制最小化、最大化/还原、关闭按钮，共享组件只显示图标和标题。主窗口、独立笔记、标签/名称编辑、历史版本、设置、移动笔记、导入、登录、提示共 9 类窗口统一；当前系统测得逻辑高度 48，DPI 按系统指标换算，不承诺固定 42。关闭按钮保留系统红色反馈，其他按钮使用中性灰色反馈。窗口关闭交回 WPF，保留模态结果、保存和托盘所需的关闭取消语义。
8. **高频新建入口集中到第二栏。** 桌面第一栏移除新建笔记按钮及其专属菜单引用；第二栏加号移至搜索胶囊右侧，按用户最终要求改为 38×38 的圆形、圆角 19、间距 8，搜索框使用剩余宽度。复用原来的 NewNoteCommand 与 Ctrl+N；布局测试确认实际尺寸、空列表时可用、命令与快捷键绑定一致，新建空白笔记测试通过。网页桌面布局同步调整并构建通过；Windows 开发版已在原项目目录更新。

## 已验证的基础流程

- 新建空白笔记、标题和正文修改、回车分段、退格合并、撤销重做、笔记切换。
- 自动保存、本地 SQLite 重新打开、列表刷新时保护待保存草稿、保存进行中继续输入。
- 图片预设 75%/50% 和实际拖拽至 327px 的保存/重新打开；删除图片后继续输入。
- 含图片和不含图片的表格笔记；公式对话框操作后继续输入；多张图片时粘贴来源只记录一次。
- 回收站只读状态切换回普通笔记后恢复编辑；跨笔记的迟到来源回复不会修改新笔记。
- 原有导入导出、备份恢复、历史版本、搜索排序、笔记本/标签、附件和同步队列测试。
- 静态检查桌面编辑器和网页端 33 个源文件的标识符作用域；剩余名称为浏览器全局或 Vite 明确定义的版本变量。

## 验证结果和复验入口

- 桌面编辑器：`npm test --prefix editor`，27/27 通过。其中桥接测试编译并挂载真实 React 编辑器，模拟 WebView 消息并检查未捕获异常。
- 网页端：`npm test --prefix web`，25/25 通过。
- Windows：原有核心测试 1/1 保持有效；接入 SDK 后非界面集成测试 81/81 通过。独立原生宿主验证消息对话框（深浅主题、确认/取消、系统关闭、Esc 和长消息）、侧栏，以及最大化/还原/最小化、正文输入和可取消关闭均通过。
- VSTest 宿主不等同于应用自己的自包含 WinRT 宿主，原生窗口测试使用 `LightNote.IntegrationTests.exe message-dialog`、`sidebar`、`window-controls` 三个独立入口；业务测试仍用 `dotnet test`。测试应用只加载实际应用资源，禁用单实例、同步和用户数据启动，避免业务启动干扰窗口测试。CI 已按此方式分组执行。
- CI 构建嵌入式编辑器前必须先运行编辑器测试；失败时停止后续构建和打包。
- 开发版目录：`artifacts/development/current/win-x64`。Tall 版本构建 0 错误、1 个既有 Skia API 弃用警告；Windows App SDK 的必要运行组件随目录交付，打包流程检查其存在。源码中的 9 个窗口均有且仅有一个共享标题栏，不再叠加旧 WindowChrome、自绘按钮或内部窗框。

## 检查边界

主窗口与独立笔记窗口共享同一嵌入式编辑器，因此编辑器修复同时适用。主机的载入、快照、保存和关闭代码已检查；未使用真实用户笔记执行编辑测试，也未人工穷举所有窗口操作。在线账号同步和远程服务没有进行实际联网验证。此次未发布云端、未构建 Android 包；未宣称软件不存在任何其他缺陷。

后续增加编辑功能时应保留这些基础回归用例，并扩展其与文字编辑、保存、笔记切换的组合测试。基础用例失败时不得交付新构建。
