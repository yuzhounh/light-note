# LightNote 第一栏右键菜单优化方案

日期：2026-10-10。状态：Windows 第一栏菜单优化已实现，专项测试通过，Release 开发版已编译，等待用户实际试用。

## 实施前源码发现（历史记录）

- 本次主要针对 Windows 桌面版。用户描述的“笔记本组”总标题菜单与桌面源码一致。Web 版 `Sidebar.jsx` 的笔记本右键已有删除操作弹窗，不能直接视为同一个实现。
- `MainWindow.xaml:138` 的 `SidebarPanel` 外层绑定了通用菜单：新建笔记本、新建笔记本组、最近笔记／未归类／回收站显示开关。子控件没有有效对象菜单时，存在使用外层菜单的路径；应限制背景菜单只能由空白区域触发。
- `MainWindow.xaml.cs:1200` 的右键处理会先选择并聚焦行，再动态生成菜单。没有菜单时仅标记鼠标按下事件已处理，不能据此认定后续上下文菜单事件已被可靠阻断。
- `CreateNotebookContextMenu`（约 1677 行）只覆盖三类：`GroupRoot` 是“新建笔记本组”；`Group` 已有重命名、删除；`User` 只有移出组／移到其他组。在没有可用分组操作时，普通笔记本菜单直接返回 null。
- Windows `INotebookRepository` 与 `MainViewModel` 尚无完整的笔记本删除操作入口；已有 `Notebook.DeletedAt` 与笔记本更新入同步队列能力。增加删除菜单需要完成数据处理链路，不能只加菜单文字。
- 源码中具体组已有删除菜单，但用户运行时未看到。需在实施时确认运行程序是否对应当前构建，以及右键命中的是具体组还是总标题、图标、文本、行内留白；当前不能把原因直接定为事件冒泡或旧安装包。
- 工作区存在大量进行中的修改。后续实施应基于当前内容做小补丁，不覆盖或回退其他改动。

## 建议的菜单分工

| 右键位置 | 建议菜单 | 说明 |
| --- | --- | --- |
| 第一栏空白背景 | 新建笔记本；新建笔记本组；“显示导航项”子菜单 | 最近笔记、未归类、回收站的显示开关集中放在子菜单内 |
| “笔记本组”总标题 | 新建笔记本组；新建笔记本 | 是系统入口，不提供删除或重命名 |
| 用户创建的具体组 | 在此组新建笔记本…；重命名笔记本组…；分隔线；删除笔记本组… | 新笔记本直接归入右键组；删除只解散分组 |
| 用户创建的笔记本 | 在此笔记本新建笔记；重命名笔记本…；“移动到笔记本组”子菜单；分隔线；删除笔记本… | 移动子菜单包含各个组与“移出当前组”；没有可用目标时隐藏该子菜单 |
| 全部笔记 | 新建笔记 | 系统视图不可删除；笔记本归属沿用明确的新建规则 |
| 最近笔记 | 打开最近笔记；隐藏此入口 | 隐藏只改变导航显示，可从背景菜单恢复 |
| 未归类 | 新建未归类笔记；隐藏此入口 | 新建笔记的 NotebookId 应明确为 null |
| 回收站 | 打开回收站；隐藏此入口 | 第一阶段不新增“清空回收站”；该功能涉及永久删除，应作为独立需求 |
| 标签（当前第一栏可展示） | 查看此标签的笔记 | 不混入笔记本删除操作；标签重命名、删除留给独立功能，不能先展示无实现的命令 |
| 顶部“新建笔记”按钮 | 新建笔记 | 复用左键动作和快捷键提示 |
| 底部账户按钮 | 未登录：Google 登录；已登录：立即同步、退出登录 | 复用现有账户操作及登录／同步状态；无需复制整个账户面板 |
| 设置按钮 | 打开设置 | 复用现有设置入口 |
| 搜索／重命名等输入框 | 保留系统文本编辑菜单 | 不被第一栏背景菜单覆盖 |

每类菜单只放与该对象直接相关且已实现的命令，不要求菜单长度相同。桌面与 Web 应共享对象语义，具体呈现可以采用原生菜单或触摸操作面板。

## 删除规则

1. 删除组：保留全部笔记本和笔记，只删除组及成员关系。现有 `DeleteGroupAsync` 已采用此规则。确认框可写：“删除笔记本组‘工作’？组内笔记本和笔记都会保留，笔记本将显示在组外。”
2. 删除笔记本：建议保留笔记，把所有关联笔记的 NotebookId 设为 null，清理组成员关系，并软删除笔记本。已在回收站的笔记保持删除状态，不因移除归属而恢复。
3. 确认框明确写：“删除笔记本‘项目’？其中的笔记会保留，并移到‘未归类’。”可展示活动笔记数量，但不应因为计数失败而改变删除语义。默认选择取消。
4. 先保存当前编辑内容，数据变更使用同一事务，并更新笔记版本／同步修订与 outbox。不能直接删除笔记本行或只在列表里移除，造成笔记仍指向已删除容器、同步重新出现或不同设备归属不一致。
5. 操作按右键目标的类型与 ID 执行，不使用可能已经变化的 SelectedNotebook。删除当前查看的笔记本后明确切换到未归类（入口隐藏时切换全部笔记），刷新列表并保留有效编辑状态。
6. 批量迁移应覆盖分页以外的笔记，不逐篇依赖当前屏幕列表。失败保持事务回滚，显示明确错误，不报告删除成功。

## 按优先级实施

### 第一步：修复菜单路由和目标识别

- 给背景、系统导航、组总标题、具体组、笔记本及底部按钮建立明确的菜单类型。
- 优先使用 `ContextMenuOpening` 统一识别目标，同时覆盖鼠标与 Shift+F10／菜单键；不要仅靠右键按下处理。
- 对背景菜单检查事件来源，排除列表行、按钮、输入框、滚动条、已打开的账户弹窗。确认是真实空白区域才打开。
- 使用 NotebookKind 和 ID 判别对象。图标、文字、整行留白应命中同一个行对象，背景不按当前选中行猜测目标。
- 打开菜单时保留当前查看状态，给右键对象临时视觉提示；执行“打开”或“新建”才切换视图。关闭菜单后清理目标，避免陈旧菜单作用于其他对象。
- 先复用已有组重命名／删除／分组移动命令，确保具体组菜单正确出现。无需数据库迁移。
- 验收：逐类右键，第一次与连续右键结果一致；取消菜单不切换正在查看的笔记；背景不出现删除；键盘菜单正确；行图标、文本、留白结果一致。

### 第二步：完成笔记本重命名与删除链路

- 增加 ViewModel 与仓储操作，复用当前命名规则、软删除和同步队列机制。
- 完成事务化的笔记归属迁移、组关系清理、版本与同步修订更新。
- 菜单接入确认框、异常处理、删除后视图回退；重命名保留笔记本 ID 与笔记归属。
- 验收：空笔记本、含多页笔记的笔记本、包含回收站笔记的笔记本；删除后笔记总数不减少，归属正确；失败回滚；同步保留软删除并传播笔记归属变更。只运行相关专项测试。

### 第三步：补齐上下文创建与按钮菜单

- 在组内直接创建笔记本，在指定笔记本内创建笔记；绑定显式目标，不能依赖先选中右键行的副作用。
- 补齐系统导航与账户／设置按钮的简短菜单，合并背景中的导航显示开关。
- 验收登录与未登录状态、同步进行中的可用性、入口隐藏与恢复、组内创建后的正确归属。
